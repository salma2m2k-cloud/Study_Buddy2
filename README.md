# Study Buddy — Flutter App

A native mobile rebuild of Study Buddy. Everything you create — tasks,
classes, notes, study sessions, and every AI conversation — is saved
**on your device**, automatically, the moment it changes. No account, no
cloud database, nothing to press "save" on.

The AI Buddy still talks to your existing Vercel backend (the same
`api/chat.js` / `api/status.js` from the web version) so the OpenRouter
key never has to live in this app.

## 1. Create the native project scaffolding

I can write Dart source files, but the Android/iOS native project
(Gradle files, Xcode project, etc.) can only be generated by the Flutter
CLI itself. So:

```bash
flutter create study_buddy
cd study_buddy
```

Then **replace** the generated `pubspec.yaml` and `lib/` folder with the
ones from this delivery (copy all files in, overwriting what's there).

## 2. Install dependencies

```bash
flutter pub get
```

## 3. Point the app at your Vercel backend

Open `lib/config.dart` — the one place this is configured:

```dart
const String backendBaseUrl = 'https://YOUR-PROJECT.vercel.app';
```

Replace it with your actual deployed Vercel URL (no trailing slash). This
is the same backend from before — nothing about it changes.

## 4. Android setup for reminders

Task and class reminders use real, scheduled OS notifications so they
still fire even if the app isn't open. This needs a few permission lines
that `flutter create` doesn't add by default.

Open `android/app/src/main/AndroidManifest.xml` and add these lines
inside the `<manifest>` tag (as siblings of any existing
`<uses-permission>` lines, before `<application>`):

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"/>
<uses-permission android:name="android.permission.USE_EXACT_ALARM"/>
<uses-permission android:name="android.permission.VIBRATE"/>
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>
```

And inside the `<application>` tag, so reminders survive a phone reboot:

```xml
<receiver android:exported="false" android:name="com.dexterous.flutterlocalnotifications.ScheduledNotificationReceiver" />
<receiver android:exported="false" android:name="com.dexterous.flutterlocalnotifications.ScheduledNotificationBootReceiver">
    <intent-filter>
        <action android:name="android.intent.action.BOOT_COMPLETED"/>
        <action android:name="android.intent.action.MY_PACKAGE_REPLACED"/>
        <action android:name="android.intent.action.QUICKBOOT_POWERON"/>
    </intent-filter>
</receiver>
```

## 5. iOS setup for reminders

No `Info.plist` changes are needed for local notifications specifically
— the app requests permission in code the first time it launches (you'll
see the system prompt). If you want a custom permission-request message,
that's the standard `NSUserNotificationsUsageDescription`-style flow
Xcode will guide you through, but it isn't required to make notifications
work.

## 6. Run it

```bash
flutter run
```

## What's actually persisted, and how

Everything the web app saved is saved here too, using
[`shared_preferences`](https://pub.dev/packages/shared_preferences) —
Android's `SharedPreferences` / iOS's `NSUserDefaults`, both fully local
to the device:

- Tasks (including completed/overdue state)
- Classes
- Notes
- Study session history
- The in-progress study session, if you close the app mid-session
- Every AI conversation, with its full message history
- Settings (theme, sound, vibration, default reminder lead time)

Every create/edit/delete/toggle writes to disk immediately — see
`lib/app_state.dart`, where every method that changes something calls
its `_persist...()` counterpart before notifying the UI. There's no
separate save step anywhere.

## Reminders — "reminded well"

This is actually **better** than the web version could be: task and
class reminders are scheduled as real OS notifications
(`flutter_local_notifications`), so they fire even if Study Buddy isn't
open, using the phone's own alarm system. Class reminders repeat weekly
automatically. The device's real timezone is read at startup
(`flutter_timezone`) rather than assumed, so times are correct wherever
you are.

## What's intentionally simplified from the web version

To keep this a focused, working first version rather than an enormous
one-shot:

- **Ambient study sounds** (the rain/white-noise/chime options from the
  web app) aren't wired up to real audio yet — that needs bundled audio
  assets or a synthesis approach I didn't want to guess at blindly. The
  Study screen works fully otherwise; this is the one feature I'd flag
  as a follow-up rather than call done.
- Screens use Flutter's own Material widgets rather than recreating the
  web app's custom CSS pixel-for-pixel — colors and type follow the same
  palette (honey/sage/coral, warm paper background), but the layout is
  native-idiomatic (e.g. a drawer instead of a fixed sidebar, push
  navigation for chat/notes instead of side-by-side panels), since that's
  what actually feels right on a phone.

Nothing else was cut — tasks, classes, study timer (accurate, real-timestamp
based, no artificial limit), notes, AI chat with per-conversation history,
and settings are all fully implemented.

## Security

- The OpenRouter API key never enters this repository or this app. The
  app only ever calls your Vercel backend's `/api/chat` and `/api/status`
  over HTTPS — exactly like the web version.
- All local data stays on the device; nothing is uploaded anywhere.
